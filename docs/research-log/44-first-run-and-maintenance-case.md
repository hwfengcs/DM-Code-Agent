## 从试用路径发现的问题

英文 README 与展厅此前指向中文快速开始，现在补齐英文安装、首次任务、报告与排障路径，
同时修正三篇英文文章的入口。已有用户询问 Xinference/Qwen，检查后发现内置 OpenAI 客户端
调用 Responses API；仅替换 `base_url` 无法适配只实现 Chat Completions 的服务。

新增 `examples/openai_compatible.py`，由 `--extension` 显式加载供应商。
它保留消息角色、要求明确 endpoint、使用独立 `DM_COMPATIBLE_API_KEY` 或无鉴权占位值，
不把现有云供应商密钥带到其他服务。重试沿用基类，SDK 内层重试关闭。
空的最终正文会报错，不把 `reasoning_content` 当成可执行动作。

协议由真实 SDK + 内存 transport 验证，包括请求路径、角色、鉴权隔离、401/429 重试和空正文。
没有运行真实 Xinference/Qwen，文档明确区分协议验证与模型能力。

## 一次真实修复，两个不同结论

[完整案例](../case-studies/failure-classification/README_ZH.md)从历史缺陷提交创建独立 worktree。
提供任务和 12 项回归检查，由当前 Agent 调用真实 DeepSeek 完成一次有界尝试。

模型补丁让针对性检查从 5 通过、7 失败变成 12 通过；更大范围的历史测试却剩下 2 项失败。
Agent 没有宣布完成，而是在继续检查时耗尽 14 步预算。另建 worktree，只应用归档补丁，
离线复现了这两个结果。历史正式修复包含额外 eval fixture 调整，本次任务只允许修改两个源码文件。

案例公开任务、给定检查、原样补丁、逐请求 token 用量、审阅后的 HTML 报告和复现输出。
原始 trace、模型运行工作区与独立复现工作区均保留在本地；完整模型 I/O 没有捕获。
Git attributes 固定证据文件字节，测试检查 SHA-256 与用量加总，避免跨平台换行破坏证据。
这不是一次新的 SWE-bench 运行，也没有形成新的总体能力分数。
